## 🌟 معرفی پروژه

**HiddiBot Pro** یک راه‌حل همه‌کاره، قدرتمند و امن برای راه‌اندازی و مدیریت کسب‌وکار فروش کانفیگ و اشتراک‌های اینترنت آزاد است. این سیستم با اتصال به وب‌سرویس **سرورهای مدیریت VPN (نظیر Hiddify Manager و هسته‌های مدرن)**، تمامی مراحل ساخت کاربر، صدور لینک‌های هوشمند، تمدید خودکار، مدیریت امور مالی و تسویه‌حساب نمایندگان را به صورت ۱۰۰٪ خودکار انجام می‌دهد.

### 🛡️ معماری پایدار و بدون کرش (Zero-Crash Safe Boot)
سامانه طوری مهندسی شده است که حتی در صورت خالی بودن تمامی متغیرهای اولیه در اولین استقرار یا پس از ریبوت سرور، بدون خطا و کرش بالا می‌آید و به صورت خودکار مدیر را به **ویزارد راه‌اندازی تحت وب (`/setup`)** هدایت می‌کند. همچنین هیچ دیتای فرضی یا ناخواسته‌ای به صورت پیش‌فرض در دیتابیس تزریق نمی‌شود تا هر نصب جدید کاملاً پاک و تمیز باشد.

## ✨ امکانات و قابلیت‌های برجسته

### 🌐 ۱. پنل وب مدیریت مرکزی (Super Admin Web Dashboard)
- **داشبورد زنده و مانیتورینگ آنلاین:** نمایش لحظه‌ای ترافیک مصرفی، سرورها، وضعیت درآمد و مشتریان فعال.
- **ویزارد راه‌اندازی گرافیکی چندزبانه (`/setup`):** پشتیبانی کامل از ۴ زبان (**فارسی 🇮🇷، انگلیسی 🇬🇧، روسی 🇷🇺 و چینی 🇨🇳**) با امکان سوییچ آنی و سوئیچ جهت راست‌چین/چپ‌چین.
- **بازیابی فوری اطلاعات:** امکان آپلود فایل پشتیبان دیتابیس (`.json` یا `.db`) در ویزارد و بازگردانی فوری تمام کاربران، سوابق و تنظیمات.
- **پیکربندی داینامیک زیرساخت:** تنظیم توکن ربات تلگرام، کلید‌های API، مسیرهای پروکسی و دامنه‌ها بدون نیاز به دستکاری فایل متنی یا ریبوت سرور.
- **مدیریت پیشرفته امور مالی و تسویه:** استرداد خودکار زمانی فیش‌ها (`<=12h: 100%`، `<=24h: 50%`، `>24h: 0%`)، ثبت تراکنش‌ها و همگام‌سازی دوطرفه با سطل زباله.

### 👥 ۲. موتور قدرتمند نمایندگی و ربات‌های اختصاصی (White-Label Multi-Bot Engine)
- **ربات تلگرام مستقل برای هر نماینده:** اتصال توکن اختصاصی هر نماینده با پیام خوش‌آمدگویی، کانال اختصاصی و برندینگ مستقل.
- **تفکیک کامل سوابق مالی و تراکنش‌ها:** دسته‌بندی استاندارد تراکنش‌های خرید، تمدید، شارژ کیف پول و استرداد وجه.
- **سیستم مدیریت بدهکاری و سقف اعتباری:** امکان فعال‌سازی خرید اعتباری برای نمایندگان منتخب با محدودیت‌های خودکار بدهی.

### 📱 ۳. ربات کاربری تلگرام و مینی‌اپلیکیشن وب (Telegram Mini-App)
- **مینی‌اپلیکیشن مدرن:** طراحی چشم‌نواز با تم تاریک/روشن و دسترسی سریع به کانفیگ‌ها و اطلاعات اشتراک.
- **پروفایل هوشمند و آواتار سه‌بعدی:** واکشی خودکار عکس پروفایل تلگرام با کش بهینه و آواتارهای سه‌بعدی آفلاین.

## 🚀 ۱. نصب خودکار تک‌خطی در سرور لینوکس (پیشنهادی)

تنها با اجرای یک دستور ساده در ترمینال سرور لینوکس (**Ubuntu 20.04/22.04/24.04**، Debian 11/12، CentOS، AlmaLinux، Rocky Linux)، کل پیش‌نیازها، پایتون، پکیج‌ها و سرویس سیستمی به صورت خودکار نصب و راه‌اندازی می‌شود:

```bash
bash <(curl -sL https://raw.githubusercontent.com/MOhammaDpirouznia/TGBot/main/install.sh)
```

**امکانات اسکریپت نصب:**
1. **انتخاب زبان در گام اول:** امکان انتخاب زبان نصب از بین فارسی، انگلیسی، روسی و چینی.
2. **بررسی پورت و تداخل:** در صورت اشغال بودن پورت پیش‌فرض (۵۰۰۰)، به صورت خودکار پورت‌های آزاد بعدی (۵۰۰۱، ۵۰۰۲ و ...) را پیشنهاد می‌دهد.
3. **محیط ایزوله Python Virtualenv:** نصب تمامی کتابخانه‌ها در `/opt/tgbot/venv` بدون ایجاد تداخل با پایتون سیستم یا سایر برنامه‌ها.
4. **ساخت سرویس Systemd مقاوم در برابر ریبوت:** سرویس `tgbot.service` را با تنظیمات خودراه‌اندازی (`enable`) و پایش وضعیت شبکه می‌سازد.

## 🔄 ۲. بررسی و تضمین اجرای خودکار بعد از ریبوت سرور (Reboot Resilience)

یکی از دغدغه‌های مهم مدیران، شروع به کار مجدد ربات و پنل پس از خاموش و روشن شدن سرور یا ریبوت‌های دوره‌ای است. در این پروژه تدابیر زیر پیاده‌سازی شده است:

### ✅ چرا پروژه بعد از ریبوت بدون مشکل اجرا می‌شود؟
1. **ثبت در لایه بوت لینوکس (`multi-user.target`):** سرویس با دستور `systemctl enable tgbot.service` فعال شده و سیم‌لینک سیستمی آن در پوشه سرویس‌های دائمی بوت قرار می‌گیرد.
2. **انتظار برای پایداری کارت شبکه و DNS:** برخلاف سرویس‌های معمولی، در تعریف سرویس از دستورات زیر استفاده شده است:
   ```ini
   After=network.target network-online.target
   Wants=network-online.target
   ```
   این تنظیم تضمین می‌کند که پروژه دقیقاً زمانی اجرا شود که اینترنت و DNS سرور متصل شده‌اند، تا ربات با خطای موقت قطعی شبکه مواجه نگردد.
3. **ری‌استارت نامحدود و خودکار در صورت خطا (`Restart=always`):** چنانچه سرور در لحظه بوت با کندی پردازنده یا قطعی اولیه اینترنت روبرو شود، سیستم‌عامل هر ۵ ثانیه یک‌بار سرویس را مجدداً بالا می‌آورد تا شرایط پایدار شود.
4. **شروع مستقل وب‌پنل حتی بدون توکن ربات:** ترد پنل وب در بدو اجرای برنامه بالا می‌آید؛ بنابراین حتی اگر هنوز توکن ربات تنظیم نشده باشد یا تلگرام فیلتر باشد، وب‌پنل مدیریت به هیچ وجه متوقف نخواهد شد.

### 🧪 نحوه بررسی و تست فعال بودن سرویس در بوت:
برای اطمینان از اینکه سرویس در بوت فعال است، دستور زیر را در اوبونتو بزنید:
```bash
systemctl is-enabled tgbot
```
> خروجی باید کلمه **`enabled`** باشد.

برای تست کامل عملکرد ریبوت سرور:
```bash
# ریبوت آزمایشی سرور
sudo reboot

# پس از بالا آمدن سرور (حدود ۱ دقیقه بعد) وضعیت را چک کنید:
sudo systemctl status tgbot
```

### 🛠️ دستورات پرکاربرد مدیریت سرویس در اوبونتو:
```bash
# بررسی وضعیت اجرای زنده سرویس
sudo systemctl status tgbot

# ری‌استارت سرویس
sudo systemctl restart tgbot

# مشاهده لاگ‌های زنده سیستم (Real-time logs)
sudo journalctl -u tgbot -f -n 50

# توقف سرویس
sudo systemctl stop tgbot

# شروع مجدد سرویس
sudo systemctl start tgbot
```

## 🤝 ۳. راهنمای جامع همزیستی بدون تداخل با سایر اسکریپت‌ها و پنل‌ها

اگر روی سرور اوبونتوی خود پنل‌های دیگری نظیر **هیدیفای (Hiddify Manager)**، **مرزبان (Marzban)**، **X-UI / 3X-UI**، **Nginx** یا **Apache** دارید، HiddiBot Pro طوری طراحی شده است که با رعایت نکات زیر با حداکثر آرامش در کنار آن‌ها همزیستی کند:

### ۱. تفکیک کامل پورت‌ها (Port Management)
- پنل‌های VPN و وب‌سرورها معمولاً پورت‌های **۸۰ و ۴۴۳** (و گاهی **۸۰۰۰** یا **۸۴۴۳**) را اشغال می‌کنند.
- این سامانه به صورت پیش‌فرض روی **پورت ۵۰۰۰** اجرا می‌شود.
- در صورتی که پورت ۵۰۰۰ سرور شما مشغول باشد، نصاب هوشمند پروژه به صورت خودکار پورت‌های آزاد (مانند ۵۰۰۱ یا ۵۰۵۰) را شناسایی و جایگزین می‌کند.
- برای باز کردن پورت پنل در فایروال اوبونتو (UFW):
  ```bash
  # اگر پورت ۵۰۰۰ است:
  sudo ufw allow 5000/tcp
  # اگر پورت دیگری انتخاب کردید (مثلاً ۵۰۰۱):
  sudo ufw allow 5001/tcp
  ```

### ۲. عدم استفاده از Certbot Standalone روی پورت ۸۰
> [!IMPORTANT]
> اگر هیدیفای، Nginx یا وب‌سرور دیگری روی پورت ۸۰ سرور شما در حال اجراست، هنگام نصب یا تنظیم دامنه **نباید** از حالت صدور سرتیفیکیت مستقل (Certbot Standalone) استفاده کنید، زیرا پورت ۸۰ اشغال است و با ارور مواجه می‌شوید.
> **بهترین و تمیزترین راه‌حل:** استفاده از **Cloudflare Tunnel (بخش ۴)** است که به هیچ پورت ورودی ۸۰ یا ۴۴۳ نیاز ندارد!

### ۳. مدیریت بهینه منابع سخت‌افزاری (RAM & CPU Capping)
برای جلوگیری از سنگین شدن سرور و افت سرعت هسته‌های ترافیکی هیدیفای و مرزبان:
- در سرویس Systemd سقف مصرف رم پروژه روی **۸۵۰ مگابایت** محدود شده است (`MemoryMax=850M`).
- حتی در ترافیک‌های بالا، پردازش‌های ربات منابع حیاتی سایر اسکریپت‌های سرور را اشغال نخواهند کرد.

### ۴. ایزوله‌سازی فایل‌ها و پکیج‌ها
- تمام فایل‌های پروژه به صورت مستقل در مسیر `/opt/tgbot` ذخیره می‌شوند و هیچ فایلی در مسیرهای `/opt/hiddify-manager` یا سایر پوشه‌ها قرار نمی‌گیرد.
- وابستگی‌های پایتون درون یک Virtual Environment مجزا قرار دارند و پکیج‌های سیستم‌عامل دستکاری نمی‌شوند.

## ☁️ ۴. راهنمای اتصال و تانل کلودفلر (Cloudflare Tunnel - دقیق و تست‌شده)

استفاده از تانل کلودفلر بهترین شیوه برای متصل کردن دامنه به پنل وب در سرورهای اوبونتو است. در این روش **آی‌پی سرور مخفی می‌ماند**، **نیازی به باز کردن پورت ۸۰/۴۴۳ نیست** و **هیچ تداخلی با هیدیفای یا وب‌سرورهای دیگر پیش نمی‌آید**.

### 🌟 روش اول (پیشنهادی و تضمینی - بدون نیاز به نوشتن فایل YAML):
1. به [داشبورد Cloudflare Zero Trust](https://one.dash.cloudflare.com/) بروید.
2. از منوی سمت چپ مسیر **Networks > Tunnels** را باز کنید و روی **Add a tunnel** بزنید.
3. گزینه **Cloudflared** را انتخاب کرده و یک نام دلخواه بگذارید (مثلاً `tgbot`).
4. سیستم‌عامل **Debian / Ubuntu 64-bit** را انتخاب نمایید.
5. کلودفلر یک خط دستور آماده به شما می‌دهد؛ آن را کپی کرده و در ترمینال سرور اوبونتو اجرا کنید:
   ```bash
   # دانلود و نصب خودکار پکیج رسمی کلودفلر
   curl -L --output cloudflared.deb https://github.com/cloudflare/cloudflared/releases/latest/download/cloudflared-linux-amd64.deb && sudo dpkg -i cloudflared.deb
   
   # نصب سرویس دائمی کلودفلر با توکن اختصاصی شما (از داشبورد کلودفلر بردارید):
   sudo cloudflared service install <YOUR_TOKEN_HERE>
   ```
6. در همان صفحه کلودفلر، تب **Public Hostnames** را انتخاب کنید و روی **Add a public hostname** بزنید:
   - **Subdomain:** ساب‌دامین دلخواه شما (مثلاً `panel` یا `bot`)
   - **Domain:** نام دامنه شما در کلودفلر (مثلاً `yourdomain.com`)
   - **Type:** گزینه `HTTP`
   - **URL:** مقدار `127.0.0.1:5000` (یا هر پورتی که در فایل `.env` به عنوان `PORT` ذخیره کرده‌اید).
7. دکمه **Save** را بزنید. کار تمام است! پنل شما روی `https://panel.yourdomain.com` با SSL معتبر در دسترس خواهد بود و پس از هر ریبوت سرور نیز خودکار فعال می‌ماند.

### 🛠️ روش دوم (راه‌اندازی دستی از طریق ترمینال - نسخه کاملاً اصلاح‌شده):
> [!NOTE]
> در راهنماهای قدیمی اینترنت، قرار دادن آدرس فایل شناسه در مسیر `/root/.cloudflared/` باعث ارور Permission Denied در زمان بوت سیستم می‌شد. مراحل اصلاح‌شده زیر این مشکل را به طور کامل برطرف کرده است:

1. **نصب پکیج `cloudflared`:**
   ```bash
   curl -L --output cloudflared.deb https://github.com/cloudflare/cloudflared/releases/latest/download/cloudflared-linux-amd64.deb
   sudo dpkg -i cloudflared.deb
   rm -f cloudflared.deb
   ```

2. **لاگین و ساخت تانل:**
   ```bash
   cloudflared tunnel login
   # لینک ظاهر شده در ترمینال را در مرورگر باز کرده و دامنه خود را تایید کنید.

   cloudflared tunnel create tgbot-tunnel
   # این دستور یک Tunnel ID اختصاصی به شما نمایش می‌دهد (مثلاً 12345678-abcd-ef01-...).
   ```

3. **انتقال فایل اعتبارسنجی به مسیر سیستمی (جهت رفع خطای مجوز):**
   ```bash
   sudo mkdir -p /etc/cloudflared
   sudo cp ~/.cloudflared/*.json /etc/cloudflared/
   ```

4. **ساخت فایل کانفیگ تانل (`/etc/cloudflared/config.yml`):**
   ```bash
   sudo nano /etc/cloudflared/config.yml
   ```
   محتوای زیر را با جایگزینی Tunnel ID و دامنه خود قرار دهید:
   ```yaml
   tunnel: YOUR_TUNNEL_ID_HERE
   credentials-file: /etc/cloudflared/YOUR_TUNNEL_ID_HERE.json

   ingress:
     - hostname: panel.yourdomain.com
       service: http://127.0.0.1:5000
     - service: http_status:404
   ```

5. **ثبت رکورد DNS و استارت سرویس:**
   ```bash
   cloudflared tunnel route dns tgbot-tunnel panel.yourdomain.com
   sudo cloudflared service install
   sudo systemctl daemon-reload
   sudo systemctl enable cloudflared
   sudo systemctl restart cloudflared
   ```

*(راهنمای کامل‌تر به همراه تنظیمات WAF و تنظیمات امنیتی کلودفلر در فایل [CLOUDFLARE_GUIDE.md](file:///d:/GitHub/TGBot/CLOUDFLARE_GUIDE.md) در دسترس است).*

## 🔀 روش جایگزین: اتصال با Nginx Reverse Proxy (بدون کلودفلر)

اگر روی سرور از قبل Nginx نصب دارید و نمی‌خواهید از تانل کلودفلر استفاده کنید، می‌توانید یک ساب‌دامین اختصاصی را با کانفیگ زیر به پنل فوروارد کنید:

```nginx
server {
    listen 80;
    server_name panel.yourdomain.com;

    location / {
        proxy_pass http://127.0.0.1:5000;
        proxy_set_header Host $host;
        proxy_set_header X-Real-IP $remote_addr;
        proxy_set_header X-Forwarded-For $proxy_add_x_forwarded_for;
        proxy_set_header X-Forwarded-Proto $scheme;
    }
}
```
پس از ایجاد فایل در `/etc/nginx/sites-available/` و فعال‌سازی آن با سیم‌لینک، با دستور `sudo certbot --nginx -d panel.yourdomain.com` گواهی SSL رسمی بگیرید.

## 🚂 ۵. سایر روش‌های استقرار (Railway & Docker)

### استقرار در سرویس ابری Railway
1. مخزن گیت‌هاب را در حساب Railway خود **Deploy** کنید.
2. **اتصال Volume (الزامی برای پایداری داده‌ها):**
   - در تب **Volumes** دکمه **Add Volume** را زده و مسیر را `/data` بگذارید.
3. **متغیرهای محیطی:** متغیرهای `DATA_DIR=/data` و `PORT=5000` را در تب Variables اضافه کنید.
4. وارد آدرس `https://your-app.up.railway.app/setup` شوید.

### استقرار با Docker
```bash
git clone https://github.com/MOhammaDpirouznia/TGBot.git /opt/tgbot
cd /opt/tgbot
docker-compose up -d
```
سپس به آدرس `http://SERVER_IP:5000/setup` مراجعه کنید.
